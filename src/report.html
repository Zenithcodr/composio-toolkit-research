      The agent and its boundaries

      Research, then try to disprove it.

      Research agents searched and opened first-party documentation, producing structured findings across the assigned apps. Python validates and consolidates their outputs. The repository also contains a separately runnable, checkpointed model-backed research client; its execution status is disclosed below.

      Find

      Start from the assigned identity. Locate official auth, API, access and MCP documentation.

      Structure

      Extract evidence-backed fields. Keep plan gates, app scopes and uncertain claims separate.

      Challenge

      Re-open ambiguous sources, run consistency checks and record corrections.

      Decide

      Publish a scoped verdict and an explicit next action, not an unsupported confidence score.

      What ran

      Agent research outputs, source URLs and timestamped records are included. Python produces the matrix and all summary counts. The recorded replay below reads those saved results; it does not launch a new paid research run.

      What remains conditional

      Gated apps were investigated through public documentation. No customer accounts were created, no paid plans purchased and no successful authenticated vendor calls are claimed.

      Proof, not a perfect-looking percentage

      Show the misses. Preserve the baseline.

      First-pass data is immutable. Corrections require a reason and source links. The 20-app human audit covers two apps per category: a seeded random pick and a lower-confidence pick.

      Documented corrections

      How accuracy is calculated

      Each sampled app has six checks: authentication, access, API type, API breadth, MCP status and verdict. Fully correct agreement is correct ÷ (correct + partial + incorrect), against the human-adjudicated reference. Unresolved and pending fields are reported separately. The same sample is used before and after correction. This is sample agreement, not a claim of accuracy across all 100 apps.

      What this review does not prove
      • Documentation-based buildability does not prove that a live credential, production approval or every endpoint works.
      • Public docs, plan limits and MCP servers change. Evidence is dated and some cases remain unresolved.
      • A vendor-operated MCP may expose only documentation search. An existing Composio toolkit is a separate fact.
      • Retrieval may miss JavaScript-only, login-gated or unindexed documentation. Not established does not mean nonexistent.
      • Human checking is labelled complete only after the author actually reviews and records it.
